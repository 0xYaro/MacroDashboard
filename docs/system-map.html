    The system in one picture

    Think of it as three layers. A deterministic measurement layer fetches numbers and scores them against rules. A judgment layer of AI runs writes prose and proposes the weekly call. A human gate on the Desk decides what becomes active. Everything meets in one Postgres database, and the web app only reads it, except for three kinds of button press.

    deterministic codeLLMhuman / UIstorage
    Layer 1 · measure

    Worker

    Pure Python with no LLM. It pulls 65 series from 13 APIs, stores every raw response, and upserts observations. It scores the active call's conditions, trigger clauses, target bands and setups, computes drift, then rewrites the mart in one transaction.

    worker/src/macro/main.py, evaluate.py, drift.py

    Layer 2 · judge

    AI runs

    Claude fills the 10 series no API serves (ISM, liquidations, State Street, and the Fed, FedWatch, tariff and geopolitics prose) and logs events. Each week it writes the call and grades last week's. GPT (OpenClaw) writes catalysts, tail risks and the holdings watch. Every AI write goes through a validator.

    agent/SKILL.md, runner.py, openclaw/

    Layer 3 · decide

    You, on the Desk

    No AI-written call goes live by itself. The Desk shows the proposal. Accept or Reject is recorded in run_request, and the runner applies it on the next tick. Refresh asks for an amendment. The web app never activates anything itself.

    web/lib/data.ts, macro_mart.decide_proposal

    Cadence facts that bite
    • Everything runs on one Mac. Sleep is fine: launchd runs a missed calendar job on wake. A power-off is not: the job is skipped, as on 27 Sept 2026. You re-run a missed morning by hand.
    • OpenClaw does catch up missed jobs; launchd does not. So after a shutdown the feeds and the worker fall out of order.
    • The worker runs every day, weekends included. The Saturday 09:30 run already carries Friday's US close.
    • Narrative and author runs skip weekends. So Monday's author reads Friday's prose plus Monday's narrative.
    • Failed scheduled runs retry once after 15 min, then stop and leave a finding. There is no loop.
    • Run caps: a run is killed at 50 min, and a claim is declared dead after 70 min.
    • The web app re-polls data every 11.5 h, and every 20 s while a run is in flight. It flags data stale when a scheduled run is more than 45 min late.
    Two feed paths, both live today

    During the shadow trial, catalysts, holdings and tail risks reach the database through the legacy path: GPT → vault note → the worker's parser. The new desk path (GPT → typed tool → validator → macro_desk login) runs in parallel as a dry run. You pay for both until cutover.

    Human gate
    None. Goes live after the rescore
    Tune
    agent/src/macro_agent/prompts.py, config/voice.md

    CLAUDE Author, Monday

    Trigger
    Runner, Monday after 10:00 once the narrative is done (Tuesday fallback)
    Reads
    A blind phase context first, with the prior call withheld; then the full context (the reveal)
    Writes
    Phase reads, scenario set, trigger clauses, targets, setups, strategies, all as proposed; last week's grade, with the Brier score computed by code
    Guards
    Reveal order enforced; validator (sums to 100, every expression run through the worker's evaluator, every trigger typed and the risk-off confirming leg typed); preflight R1–R12; waivers recorded as findings
    Human gate
    Accept or Reject on the Desk
    Tune
    agent/SKILL.md, runner.py prompt text, preflight.py

    CLAUDE Amend, on Refresh

    Trigger
    You press Refresh (or insert an amend row)
    Reads
    The amendment context plus macro_mart.drift and your reason text
    Writes
    Amended scenario set, strategies or setups as proposed, or a NO_CHANGE line
    Guards
    Re-price only on a "material" change (a trigger fires in full, a phase condition flips, a tail risk turns acute, or a premise moves); never a phase call
    Human gate
    Accept or Reject
    Weak spot
    An amendment inherits the accepted clauses; for a migrated week that are all manual (W39), the model still decides what counts as material

    Where to optimise, ranked by leverage

    1
    Type the conditions. ENFORCED FOR NEW WEEKS W39, migrated from the journal, has 0 of 9 clauses typed, so the whole daily scoring layer produces nothing for the call itself, and drift and Refresh fall back on the model's reading. Typed clauses turn "did S2 fire?" into a fact the Desk shows at 09:30, before any AI runs. This is the biggest quality lever in the system, and it costs nothing at runtime.
